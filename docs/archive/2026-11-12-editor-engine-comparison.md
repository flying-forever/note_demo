# 长文编辑引擎对照记录

记录日期：2026-11-12。方向与当前决策见[技术实验现状](../technical-demos.md)。本轮只用独立实验和合成文字，不迁移正式数据。

## 原生路线有限核对

本机 API19 的 `component/rich_editor.d.ts` 控制器提供片段增删、选区及布局查询，未找到应用可控制的内部视口、懒排版或数据源接口；`text_common.d.ts` 的 LayoutManager 是排版查询接口。此结论不等于引擎内部没有优化。[官方 RichEditor 指南](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-Guides/arkts-common-components-richeditor/)中的最大显示行数不能作为虚拟排版保证。

旧脚本在全文核对后才采内存，读回全文可能污染加载结果。本轮给 `--isolated` 增加核对前快照；真机 DMG-W00、OpenHarmony-6.1.1.120，十万 UTF-16 单元密集多段、5715 排版行，每项独立重启应用后单次采样：

| 原生模式 | 至空闲帧 | 空页总 PSS / KiB | 核对前总 PSS / KiB | 核对后总 PSS / KiB |
| --- | --- | --- | --- | --- |
| 普通逐片段 | 1382 ms | 67073 | 264870 | 282905 |
| StyledString 批量 | 806 ms | 65138 | 863705 | 940349 |

上述运行的是设备已有的原生实验实现，其逻辑与本分支原生实验页一致；只修改宿主侧采样脚本。核对前后的增长说明读回有成本，但批量路径核对前已高占用，不能将旧结果全部解释为核对开销。没有证明具体 setter、排版或 SDK 泄漏归因；普通模式仍会准备约34个未使用的样式对象，模式切换后控制器内容释放亦未证明。这里只做有限归因，不重建局部原生编辑器。

原始报告位于忽略目录 `note_by_agent/build/verification/note-native-editor-77uKH1`（逐片段）、`note-native-editor-uXji10`（批量）。快照不是峰值，计时不是冷打开或像素首帧；两项视觉区域与后续 Web 实验未严格匹配，不直接据此给出性能倍数。

## Web 对照范围

使用锁定版本的离线 CodeMirror 6，在鸿蒙 Web 组件中保留完整文字模型，仅渲染视口附近节点；从 ArkTS 传入与原生试验相同的 `fixtureText`。事务替换、撤销重做属于模型行为检查，不能代替输入法或手指选区验收。全文核对在显式按钮触发，不在每次输入时读回全文。

加载计时从 Web 内模型创建至双 requestAnimationFrame 回调，不包含 ArkTS 生成与桥接、Web 冷初始化或像素首帧。Web 可能有独立渲染进程，主应用 PSS 不能当作全部 Web 成本。

### 首个独立进程样本

构建成功（37 s 901 ms），覆盖安装并启动通过。`node scripts/validate-web-editor-demo.cjs --isolated --paragraphs --input` 在上述设备通过十万字密集多段：全文逐字符一致、事务替换及撤销/重做/恢复、模型全选、顶部/中部/尾部目标进入视口，末尾系统注入 DEMOINPUT 后严格等于原文加9字符。命令注入使用 `uitest uiInput text`，不是物理中文输入法。

模型5715行；顶部仅34个 `.cm-line`，中部73个，尾部37个，完整模型始终保留。Web内模型创建至双动画帧记录33 ms，仅单次。原生逐片段有交替色，Web为统一文字样式；视觉区域和计时覆盖也不同，不能宣称约40倍加速。

### 四场景行为回归

`node scripts/validate-web-editor-demo.cjs --input` 最终通过2万/10万×无换行/多段全部四场景，均包含全文一致、事务替换/撤销/重做/恢复、模型全选、顶部/中部/尾部目标出现在visibleRanges及系统尾部输入。模型检查不等于物理输入法、原生选区手柄或真实剪贴板通过。

| 字符数 | 场景 | Web内加载至双动画帧单次记录 |
| --- | --- | --- |
| 20000 | 无换行 | 71.2 ms |
| 20000 | 多段 | 48.7 ms |
| 100000 | 无换行 | 136.7 ms |
| 100000 | 多段 | 64.1 ms |

同一进程连续切换，非冷打开、多次统计或正式性能阈值。无换行场景只有一个逻辑行，viewport可能覆盖整行，应看visibleRanges，不能只用DOM行数证明细分范围。实验重载会保留部分旧滚动位置，状态文案亦会改变少量可视高度；长行的估算总高度在定位后会修正，尚未验证视觉锚点稳定或精确位置恢复。

最终证据为 `note_by_agent/build/verification/note-web-editor-ds5WRt/results.json`。前一次四场景尝试 `note-web-editor-jRfNSd` 停在结束编辑按钮被浮动键盘遮挡；脚本改为识别输入法窗口并先收起后重跑通过，不能解释成编辑器吞字。
