# 动态皮肤首版合入后的结构重构计划

> 归档日期：2026-11-12。本文为历史计划；R1～R4 结构迁移已实施，但阶段出口未全部验收，不应把全文当作待执行任务。剩余验收见[项目进度](../progress.md)。


状态：2026-11-11 已合入动态皮肤并实施 R1～R4 结构迁移；构建与模型/存储回归通过，核心真机回归进行中，尚未宣称所有阶段出口完成。实际模块、验证证据及未验收事项见[本轮集成记录](2026-11-11-integration.md)。以下保留原计划作为验收依据。

## 目标与范围

为统一持久化、自动草稿和长笔记建立清晰的职责边界，使主编辑页、半模态编辑与桌面扩展共用业务规则，减少修改一个功能时影响其他功能的范围。本轮保持现有对外行为和数据兼容；动态皮肤合入后的行为也纳入基线。

本轮不实现数据库、自动草稿、10 万字按需渲染、提醒或私密，也不扩展动态皮肤功能。数据库与长文的技术试验可用于验证接口设计，其正式实现仍按 [持久化计划](../plans/persistence-plan.md) 推进。已知交互问题单独记录和修复，不在结构迁移中顺手改变。

## 基本原则

1. 先明确行为，再移动代码。建立功能与数据基线，将现有缺陷和预期行为分开；重构保持基线，修复缺陷采用独立改动和验收。
2. 按职责拆分，不以行数、目录数量为目标。优先消除业务规则重复和依赖混杂；只在存在不同职责或真实复用需求时增加模块，不为每个函数创建接口。
3. 每项状态有明确所有者。编辑草稿与历史由编辑会话管理；焦点、组件挂载和弹层等 UI 状态由页面或组件管理；已提交数据由存储入口管理。界面订阅会话变化，避免两份草稿互相同步。
4. 业务规则统一，输入方式可以不同。主编辑页与半模态页共用空白判断、保存、版本冲突及删除规则，分别保留自己的布局、键盘和会话关闭方式。
5. 存储与系统功能分离。存储层不导入卡片展示和刷新 API；业务保存成功后再通知桌面适配模块。卡片更新失败不能伪装成笔记保存失败，也不能回滚已经成功的保存。
6. 小步迁移，每步可运行、可回退。保留旧调用入口作为短期适配，每迁完一个调用链再移除旧实现，不长期维护两套权威数据。接口调整和大范围格式化、重命名分开。
7. 兼容现有数据和入口。保留笔记、块、附件、卡片 ID 以及皮肤配置；未知皮肤配置可安全回退。皮肤展示配置不得混入运行时控制器、计时器或页面对象。
8. 以风险决定验证深度。数据与文本语义用自动检查，焦点、中文预输入、键盘、卡片生命周期和动态皮肤资源释放必须真机验证。测试关注行为和边界，不绑定拆分后的内部实现。

## 建议的职责边界

| 职责 | 负责 | 不负责 |
| --- | --- | --- |
| 正文与笔记模型 | 有序正文块、空白判断、纯文本导出、摘要与历史规则 | 文件 IO、卡片 API、组件焦点 |
| 编辑会话 / ViewModel | 草稿、编辑操作、撤销重做、活动位置、脏状态和保存结果 | 创建 UI 节点、控制键盘、渲染皮肤 |
| 笔记业务入口 | 主编辑与半模态共用的保存、删除、移动、换肤及冲突处理 | 具体布局、JSON 路径、数据库 SQL |
| Repository | 读取、写入、版本与迁移契约；本轮保留现有存储适配 | 卡片配色、系统刷新、提示文案 |
| 附件管理 | 导入文件、附件引用与保留/清理规则 | 文字编辑、图片操作栏布局 |
| 平台适配 | 分享、媒体选择、卡片发布/刷新及启动参数解析 | 自行维护另一套笔记保存规则 |
| 皮肤模型与展示 | 皮肤配置解析、背景绘制、动态资源启动/暂停/释放 | 笔记保存、撤销、页面导航 |
| 页面与 UI 组件 | 展示、事件转发、焦点与挂载、弹层、手势 | 直接读写笔记文件、复制保存规则 |

依赖方向以页面 → 会话/业务入口 → 模型与 Repository 为主。系统扩展通过同一业务入口工作；桌面通知由业务入口协调。接口只覆盖当前真实用法，数据库具体结构和长文渲染实现留给后续技术验证决定。

## 执行顺序与阶段出口

### R0：合入动态皮肤，建立可复现基线

- 合入后核对实际差异、存储字段、渲染节点、异步资源和生命周期，不继续沿用合入前的文件位置假设。
- 记录统一基线提交与设备环境。检查主编辑页、桌面入口、半模态页及现有测试是否仍可运行，区分合入缺陷与原有待修问题。
- 补充动态皮肤的状态切换、后台/前台、离页释放、文件兼容和卡片展示策略。卡片采用何种动态/静态展示，以皮肤首版实际能力和已确认需求为准；不明确的产品行为先确认。
- 产出职责/依赖清单、状态所有者清单、数据读写路径、风险优先级与回归清单。定位潜在数据丢失、并发覆盖、附件误删等问题时，先独立修复阻塞项。
- 出口：合入版可构建、可安装，核心行为可复现，重构范围和待修项已区分。

### R1：统一数据与业务入口

- 审查 NoteStore 与 DesktopNoteRepository，先把存取、卡片关联、卡片展示数据和系统刷新拆清，保留当前内存/选择性 JSON 行为与兼容适配。
- 主编辑页和半模态页通过同一业务入口保存、删除和更新笔记，统一空白规则、冲突结果与失败分类。
- 明确多进程读取、刷新与版本契约，不用进程内单例或事件总线假定跨进程共享。现有快照比较不等同于原子并发控制；数据库阶段再以事务完成版本检查与写入的一致性。
- 出口：现有桌面存储回归通过，两个编辑入口都可保存，重启与删除标记兼容；存储层不再依赖卡片 UI 与系统刷新。

### R2：从主编辑页提取编辑会话

- 先迁移正文操作与历史，再迁移脏状态、保存协调、外部修改处理；按调用链逐步替换，不一次搬走整页所有状态。
- 为 ArkUI V1 状态绑定做小范围验证：稳定块 ID、当前数据读取、中文预输入、焦点切换、撤销恢复和图文结构变化后继续输入均正常，再扩大迁移。
- 逻辑上的活动位置由会话记录，实际 FocusController 调用留在 UI；避免异步回调在离页后更新已销毁界面。
- 本轮保持现有历史与全文导出语义。局部历史、增量字数和范围读取在长文阶段实现，不借拆分之机提前重写。
- 出口：页面不再直接实现历史与正文操作规则；纯文本、图片、撤销、键盘收起、主/半模态保存行为保持一致。

### R3：分离附件、平台能力和皮肤生命周期

- 将图片文件操作与引用清理归入附件模块，列清笔记、当前草稿、撤销历史和正在导入文件的保留条件；必要修复单独验收。
- 提取分享与卡片适配，统一启动目标解析和导航请求；重复打开的产品行为作为独立修复项处理，避免把路由变化混入代码搬迁。
- 按动态皮肤首版实际结构封装背景与资源生命周期，明确编辑/浏览、切换皮肤、打开覆盖层、后台/前台和销毁时的行为。事件监听和异步任务需要对应的释放或失效处理。
- 出口：页面不直接操作附件文件；分享和桌面入口可用；动态皮肤状态切换及资源释放通过真机验证。

### R4：整理 UI 边界与完成验收

- 按独立职责提取导航、正文块视图、图片操作层、皮肤选择等必要组件；迁移一个组件后先验证状态绑定，不一次拆成大量小文件。
- 保持输入节点身份与活动控件，迁移前后检查滚动、焦点、键盘、弹层遮挡和手势，特别回归此前的输入回退故障。
- 所有调用者迁移完成后删除兼容入口和重复实现，更新目录约定、页面规格、数据模型及系统能力记录。
- 出口：构建、数据回归与真机核心回归通过；代码不存在两套保存规则或两份权威草稿；已知缺陷和未验收场景继续明确列出。

## 验证、变更与回退

- 每阶段按独立功能闭环拆分，每次只迁移一个职责或调用链。每个变更记录改动目的、影响入口、验证结果和回退条件；需要提交时遵循用户授权，不自动 commit/push。
- 数据检查覆盖文字/换行一致性、历史、仅含图片、保存失败、删除标记、桌面关联和外部修改。迁移前后使用相同输入比较结果。
- 真机检查覆盖标题/正文切换、连续输入与删除、中文预输入、真实粘贴、插图后输入、图片操作、撤销重做、皮肤切换、后台恢复、卡片冷/热启动与半模态保存/取消。
- 中途出现数据损坏、文字变化、输入回退、焦点丢失或皮肤资源未释放，先停在当前迁移点定位；保留可复现用例，修复并回归后再推进下一步。
- 本轮不做破坏性数据迁移，旧文件与字段继续兼容；按阶段回退到已验证代码。进入数据库迁移后，数据回退另按 [持久化计划](../plans/persistence-plan.md) 设计，不能只依靠 Git 回退。

## 与持久化计划的衔接

本轮已按 R0～R4 推进，阶段出口以实际验证记录为准。持久化阶段 1 的技术验证可与结构设计相互校验，试验代码保持隔离，不提前迁移正式数据。R1～R4 验收完成后，再正式进入数据库阶段 2，沿已建立的业务入口替换存储适配。

数据库、自动草稿、局部历史和按需渲染分别沿 [持久化计划](../plans/persistence-plan.md) 后续阶段实现，避免本轮先重写一遍、下一轮再推倒重来。重构完成的标准是职责清晰、行为稳定、后续替换有明确入口，不是文件变短或一次解决所有性能问题。
