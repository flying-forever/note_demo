# Web 长文性能基线验收记录

日期：2026-11-12。设备 DMG-W00 / OpenHarmony-6.1.1.120，当前实验为离线 CodeMirror 6 文字原型。验收门槛统一见[临时性能基线](../plans/persistence-plan.md#临时性能基线2026-11-12-用户暂时采纳)，本页只记录证据、结果与缺口。

## 范围与口径

本轮优先筛查十万字无换行、密集多段的连续滑动与普通输入/退格。每轮6次系统手势，第一手势额外抓 `graphic + multimodalinput + nweb` 系统 trace；文字用系统注入36字符，再退格12次，最终严格核对原文加剩余24字符。没有接入正式存储或修改个人数据，不代表数据库读取、图片或物理中文输入法通过。

系统 trace 以 `HandleTouchEvent touchStatus_:2/4` 界定按下/抬起，`RecordMergedPresentTime` 的内嵌纳秒数是呈现时间；不能使用该行读取历史 fence 的时间代替。只统计实际触摸区间内的相邻呈现时间，另报首响与尾部等待，不能裁掉首响后宣称整段通过。`RosenWeb` 缓冲获取时间用于确认Web更新节奏，不是光子时刻，也未与每个呈现帧作严格因果配对。系统呈现是屏幕级，视觉跳文和惯性尾段另验。

浏览器回调间隔只作辅助；输入按插入/退格和可信事件分别计数，按事务 input/delete 类型匹配，从事件收到到对应模型变化及双动画帧回调。该口径不含硬件/输入法排队及物理显示，因此即使低于100ms也只记自动筛查通过，端到端仍待验。采样不在每次输入时复制全文，期间不刷新状态文字，结束才汇总。

## 系统持续触摸段（三轮）

证据：`note_by_agent/build/verification/note-web-editor-OAKFhG/performance-results.json` 及6份 trace。每种样本3轮、每轮第一手势约2秒；同一进程连续运行，设备活动时约90Hz。下表为各轮P95与所有轮最大值，不是把P95再平均。

| 十万字场景 | 各轮呈现间隔P95 / ms | 最大内部间隔 / ms | 按下至首次呈现 / ms | 判断 |
| --- | --- | --- | --- | --- |
| 无换行 | 11.15 / 11.15 / 11.17 | 22.29 | 104.89 / 104.25 / 95.42 | 内部帧间隔低于门槛；首响两轮略超100ms，保留待验 |
| 密集多段 | 11.15 / 11.18 / 11.15 | 66.66 | 24.80 / 21.05 / 44.05 | 本组持续触摸段内部间隔满足门槛；跳文与惯性尾段待手验 |

Web缓冲获取间隔P95分别为11.29～11.49ms、11.30～11.43ms，与系统持续更新一致。以上内部间隔均未超过100ms，不据此推断所有滚动或首次响应全部通过。无换行首次移动至首次呈现为86.46～95.75ms；按下至首响包含手势识别等成本，不能直接归因长文排版。

## 采样修正与复验

初版 composer fps 转储包含手势开始前静止区间，出现166～644ms间隔；trace确认旧present发生在触摸前，因此它们不是手势中的冻结。仍保留原始报告，不直接删除长间隔，而以实际触摸时间界定统计范围并另报首次响应。

初版Web回调采样可能漏掉活动结束时跨越的长间隔；输入混合记录也不能分别证明插入与删除。已改为保留区间起点或终点活动的间隔，分别统计插入与删除的可信事件，暴露未匹配与双动画帧未完成样本，结束后排空再判定。上表系统trace不受这两处Web采样修正影响；旧版Web输入混合数值不作为本轮最终分项验收。

一次初始三轮尝试 `note-web-editor-8mIw92` 停在浮动键盘遮挡开始采样按钮，修正为先开始采样再唤起输入。修正后的Web采样复验结果另列，不把失败尝试记为通过。

修正版构建成功（34 s 208 ms）、覆盖安装通过。`node scripts/validate-web-editor-performance.cjs --trace --repeat=1` 对两种样本复验，证据为 `note_by_agent/build/verification/note-web-editor-utFM7V/performance-results.json`：

| 十万字场景 | 持续触摸呈现间隔P95 / 最大值 | 活动Web回调间隔P95 / 最大值 | 插入按键→Web更新及双动画帧P95 | 退格同口径P95 |
| --- | --- | --- | --- | --- |
| 无换行 | 11.15 / 44.45 ms | 12.8 / 24.6 ms | 21.1 ms | 25.1 ms |
| 密集多段 | 11.16 / 11.30 ms | 12.7 / 39.3 ms | 32.3 ms | 29.0 ms |

每种样本都有36个可信插入按键、36个可信插入beforeinput及12个可信退格按键，48次正文变化；待匹配和双动画帧未完成样本均为0，最终全文严格一致。插入beforeinput→双动画帧P95为20.3/31.4ms。自动化按键/退格代理低于100ms，不能替代物理中文输入与端到端显示。

复验按下至首个呈现分别为51.52/106.60ms，首次移动至呈现为36.44/97.34ms。多段本次首响超过100ms，脚本明确标为 `active_intervals_within_baseline_boundary_pending`，不记整个滑动场景完全通过。以上活动内部间隔无>100ms，仍需真实快速滑动、惯性尾段和视觉锚点验收。

## 尚未验收

- 完整打开到可操作、位置恢复的端到端时延。
- 物理中文预输入/候选词/退格/收起后继续输入、手指跨屏选区与视觉跳文。
- 2万字真实剪贴板粘贴及撤销、图文适配、10轮页面生命周期内存及最终预算。

当前决策：未见持续触摸段出现此前全量RichEditor那类长时间卡顿的证据，Web文字候选值得继续；先补上述产品验收，不追逐更小的回调数字，不进入正式数据库迁移。
