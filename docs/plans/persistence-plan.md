# 本地持久化与长笔记开发计划

状态（2026-11-12）：阶段 1 按“评估完成、不阻塞后续开发”收尾，阶段 2 可启动。阶段 1 的证据与缺口见[技术实验结论](../technical-demos.md)，剩余回归见[项目进度](../progress.md)，历史验收依据见[重构历史计划](../archive/2026-11-12-refactoring-plan.md)。

## 已确认范围

- 使用本地关系型数据库保存笔记、正文块、附件信息和编辑位置；图片等二进制内容保留在应用私有文件目录。设置使用独立的小型键值存储。
- 正文文字直接保存在正文块记录中，一条笔记关联多条有序正文块。JSON 可用于块的扩展属性，不把全文作为单个 JSON 附件。
- 正文块表为权威存储。Web 引擎初期一条笔记一个块，块粒度是运行时参数；后续拆细只调整写入与读取策略，不改表结构。
- 支持 10 万字笔记，覆盖无换行长文、多段文字和图文混排。内部拆块不增加换行，不改变原文、复制和分享结果。
- 块采用目标大小、内容边界和硬上限结合的策略。约 2,000～4,000 字符、硬上限约 8,000 字符仅为试验起点，以真机测量确定；不得切断完整字符。局部拆分、合并，不因普通输入重切全文。存储块、语义段落和输入控件不强制一一对应。
- 全局设置提供恢复上次编辑位置开关，每条笔记分别记位置。开启后以浏览态打开并定位，不弹键盘；关闭后从顶部打开。位置记录不更新笔记修改时间或首页排序。
- 使用块 ID、块内光标偏移和内容版本定位；标题位置单独标识。浏览位置与编辑位置分开，单纯滚动不覆盖编辑位置。删除、拆分、合并和撤销后校正锚点，无有效锚点时回退到邻近位置或正文末尾。
- 编辑页先读取、显示目标附近内容，其他部分按需读取和渲染。用估算或缓存高度占位，实际测量后修正；保持可见内容锚点稳定，允许滚动条初始比例不精确。宽度、字号等排版条件变化时使旧高度缓存失效。
- 编辑停顿时自动保留草稿，离页正式保存；已有笔记移动、换肤立即保存相关字段，新草稿随首次内容保存。保存失败保留草稿并提示，离页正式保存失败时留页重试。
- 空白新草稿不创建笔记；清空已有笔记不自动删除；仅含图片有效。撤销重做历史离页清空，不跨进程恢复。
- 首页单独读取摘要和元信息；输入、字数和历史处理避免逐字复制、序列化全文。完整分享、复制等操作覆盖未加载内容。
- 首次初始化可导入样例，删除全部笔记后不重复生成。数据结构有版本及迁移机制。首期保证进程重启恢复，云同步、卸载恢复、导入导出、回收站与私密保护不在本轮范围。
- 图片原图入库前压到长边 1600、质量 80，目标不超过 500KB；压缩暂为空实现，超限图片拒绝入库。正文只存附件 ID 和缩略图引用，缩略图长边 960、质量 75，按视口懒加载并可淘汰。图注延后到完整 demo。
- 撤销采用事务级历史，按键合并窗口 1 秒；粘贴、插图、删除选区各自独立一步，不采用整篇快照历史。
- 编辑页与笔记一一对应，返回即销毁；不跨篇复用 Web 组件。
- 动态组件创建（`BuilderNode` / 组件复用）不进入首版方案，只在阶段 6 内存复验不通过时作为对照项评估。

## 阶段 1：现状核对与技术验证（已收尾，不阻塞后续）

阶段 1 已取得足够证据支撑数据契约与编辑引擎方向，剩余缺口不影响表结构和 Repository 设计，按“评估完成、不阻塞后续开发”收尾。

### 已通过的硬门槛

- 中文输入手验：预输入、选词、退格、收起键盘后再输入正常（当前设备、小艺输入法）。
- 浏览/编辑分离：只读态原生选区、菜单、边缘自动滚动，不弹键盘；点按进入编辑后键盘弹出、光标落点正确。
- 2 万字系统剪贴板粘贴与撤销：单事务，页面内 70.2ms，撤销后全文逐字一致。
- 十万字加载：页面内 34～37ms；滑动帧 P95 13ms、最大 58.4ms；中/尾跳转 25～50ms 且目标可见。
- 按键注入：硬件键产生可信事件，字母键 P95 32.1ms、退格 28.7ms，无 >100ms（不含中文输入法与显示呈现）。
- 图文基本链路：内置 JPEG 经沙箱转 data URI 可插入、随滚动/跳转保持、撤销与退格删除，正文长度与图片计数一致。

### 已评估、待复验（不阻塞阶段 2）

- 内存：同进程连续 20 次重载十万字，PSS 206→253MB 未收敛；增长在 GL/Graph/native heap，ArkTS 堆仅 5.7MB。正式版每篇一个编辑页、返回即销毁，暂记为 v1 已知风险，阶段 6 复验。
- 首响：仍缺可信首帧测量链路，阶段 6 用系统 trace 复核，不用页面内 `loadMs` 代替。
- 冷打开：页面内加载 34～37ms，应用冷启动出窗约 1.7s；温暖应用内“点入口到可操作”待最小入口落地后补测。
- 真实相册选图、附件表、图注、图片剪贴板粘贴：分别后置到阶段 2、阶段 3 与完整 demo。
- 视觉锚点与真机手感：滑动、跳转、插图、撤销、中文输入仍需用户真实操作确认。

### 收尾决定

- 阶段 2 可立即启动，不再等待性能门槛全绿。
- 若后续引擎改回原生，阶段 4、5 按原生分块方案重写，并回到阶段 1 补验对应项。
- 阶段 1 的详细证据只在技术实验与归档记录维护，本计划不重复贴数据。

### 临时性能基线（2026-11-12 用户暂时采纳）

先在当前真机 DMG-W00 / OpenHarmony-6.1.1.120 验收十万字无换行与密集多段两种场景；其他设备及图文覆盖另记，不据单设备结果扩大结论。

| 操作 | 验收门槛 |
| --- | --- |
| 打开笔记 | 从打开操作到目标位置可见且可操作不超过1秒，进入编辑后不再明显卡住 |
| 连续滑动 | 帧时间P95不超过33ms，无超过100ms冻结、明显停顿或跳文 |
| 普通输入与退格 | 按键到文字显示更新P95不超过100ms，连续输入不积压、不丢字 |
| 中文输入 | 预输入、选词、退格和光标移动正常，无明显延迟或文字错乱 |
| 中部/尾部定位 | 500ms内显示目标附近内容，后续排版修正不推走正在看的文字 |
| 长文粘贴 | 粘贴2万字后1秒内恢复可操作，内容和撤销结果正确 |
| 内存与稳定性 | 连续打开、编辑、退出10轮不退出、不持续增长；先采稳定占用，再确定明确内存预算 |

按实际端到端操作计时并保留冷/热启动、样本数量、设备与输入方式。帧时间应对应实际显示提交，输入延迟应覆盖按键至屏幕更新；Web requestAnimationFrame、事件回调或事务计时仅作筛查代理，不直接宣称完整达标。系统注入不能替代物理中文输入，视觉跳文、选区及中文行为需真实操作验收。结果逐项标为通过、未通过或待验；缺少测量链路时保留待验，不用已有加载数字填补。方案达标后才比较内存和维护成本，避免无目标追求更小数值。内存一项在 v1 记为已知风险，阶段 6 复验并决定是否豁免或限缩范围。

## 阶段 2：持久化基础与已有数据迁移

目标：把数据契约落成版本化数据库与 Repository，完成现有 JSON 数据迁移，主应用、卡片和半模态读同一份数据。

- [ ] 表结构定稿：笔记、正文块、附件、编辑位置、设置、schema 版本；字段、约束、索引和默认值写入[数据模型](../data-model.md)。
- [ ] 块表与整篇文档的转换契约：初期一条笔记一个块；定义“整篇读入、差异回写”的接口；普通输入不重切全文，块内偏移与内容版本可校验。
- [ ] 建立 Repository、事务封装和版本化打开流程；读写失败有明确错误类型，不静默重置。
- [ ] 接通笔记创建、读取、更新、删除、文件夹移动和换肤；首页只读摘要与元信息，不读全文。
- [ ] 迁移现有桌面笔记 JSON、删除标记、卡片关联与附件引用；迁移可重复执行、中断可恢复，成功前保留原数据。
- [ ] 主应用、桌面卡片、半模态编辑统一版本检查；冲突时保留内容并提示，不覆盖更新。
- [ ] 初始化样例与“删光不复生”标记接入数据库。
- [ ] 验收：重启恢复、迁移重试、删光不复生、图文/移动/皮肤恢复、多入口冲突、写入失败、卡片刷新。

## 阶段 3：自动草稿与附件安全闭环

目标：草稿与正式笔记分离，图片先可靠落盘再提交引用，清理不误删。

- [ ] 自动草稿表与状态机：编辑停顿写入、离页正式保存、首次草稿身份、空白草稿清理；生命周期回调作为补充。
- [ ] 恢复草稿时校验正式版本，避免覆盖其他入口的修改。
- [ ] 附件写入顺序：先写沙箱文件、校验尺寸与体积，再在事务中提交附件记录与块引用；失败回滚并清理临时文件。
- [ ] 缩略图作为派生文件管理：可重建、可删除，不进入附件主记录；缓存命中与失效规则明确。
- [ ] 清理规则覆盖正式笔记、草稿、活跃撤销历史与进行中的导入；仅完全无引用时删除原图。
- [ ] 验收：编辑中强杀进程后恢复图文草稿、保存失败重试、撤销恢复图片、删除后无引用附件被清理、跨进程孤立附件清理。

## 阶段 4：长文编辑接入与历史（Web 路线）

目标：把 CodeMirror 整篇模型接入正式数据流，保证长文输入、撤销、字数与位置正确。

- [ ] 新建最小真实外壳 `pages/NoteEditorWeb.ets`：路由参数 → 按 ID 读笔记 → 标题 → Web 正文 → 离页保存 → 返回；暂不接皮肤、分享、选图与菜单，避免复制整份约 850 行的页面。
- [ ] 双轨期共用 `NoteEditorSession` 与保存服务，保存规则只有一份；正文撤销归引擎，标题撤销仍走会话；引擎定稿后删除落选页面。
- [ ] 编辑页加载：按笔记读取块并拼成整篇文档；目标位置优先，禁止先全文渲染再滚动。
- [ ] 保存：整篇文档差异回写块表，块边界保持稳定；保存失败留页重试。
- [ ] 撤销：事务级历史，按键合并窗口 1 秒；粘贴、插图、删除选区各自独立一步；离页清空。
- [ ] 字数与摘要增量维护，输入路径不逐字复制或序列化全文。
- [ ] 位置锚点：块 ID + 块内偏移 + 内容版本；浏览位置与编辑位置分开，滚动不覆盖编辑位置。
- [ ] 图片块：正文存附件 ID，缩略图按视口懒加载并淘汰；插入、撤销、删除后计数与长度一致。
- [ ] 浏览/编辑态切换与系统选区保持现有行为；中文输入、粘贴、删除回归。
- [ ] 外壳稳定后，从 `NoteEditor` 抽取共享外壳（读参、标题、返回、保存生命周期、工具栏），两条轨道复用，结束布局双份维护。
- [ ] 验收：10 万字单段与多段输入/删除、长文粘贴、插图与撤销、逐字符原文一致、字数与摘要正确。
- 若引擎定为原生：本阶段恢复“局部拆分、范围读取、增量写入、跨块光标与选区”的原方案，并重做验收。

## 阶段 5：位置恢复与渲染边界

目标：位置恢复可用，浏览态不弹键盘，排版变化不推走正在看的文字。

- [ ] 保存与恢复编辑位置、浏览位置；开关关闭时从顶部打开。
- [ ] 恢复后以浏览态展示，不聚焦、不弹键盘；点按才进入编辑。
- [ ] 锚点失效回退：块被删、版本不符、偏移越界时回退到邻近位置或正文末尾。
- [ ] 宽度、字号、皮肤变化使高度缓存失效；图片高度变化后修正可见锚点。
- [ ] 快速滚动与长距离跳转不出现可见空白或跳文；滚动条初始比例允许不精确。
- [ ] 验收：顶部/中部/尾部恢复、开关切换、锚点失效、长距离滚动、排版变化、恢复后不弹键盘。

## 阶段 6：综合验收与文档收尾

目标：按临时基线完成端到端验收，明确豁免项，文档与实现一致。

- [ ] 性能全项：打开、滑动、输入、中文输入、定位、粘贴、内存；内存复验同进程进出笔记 10 次，必要时再做路由页 / `BuilderNode` / 复用组件的 A/B/C 对照。
- [ ] 首响用系统 trace 复核；冷打开走正式笔记入口，应用冷启动单列。
- [ ] 图文链路：500KB 上限、超限拒绝、缩略图懒加载与淘汰、插入/撤销/删除、图注回到完整 demo 范围后再验。
- [ ] 回归短笔记、中文预输入、真实剪贴板、删除、图片、皮肤、移动、桌面卡片和半模态编辑。
- [ ] 双轨收口：删除落选编辑页，共享外壳只保留一份，路由与调试开关清理。
- [ ] 更新数据模型、页面规格、系统能力与项目进度；未通过项明确记录，不以构建通过替代性能验收。
- [ ] 明确 v1 豁免范围与复验时点，避免用“已评估”代替“已通过”。

## 依赖与实施边界

阶段 2 → 3 → 4 → 5 → 6 顺序推进；阶段 1 不再阻塞。阶段 2 的表结构与 Repository 可立即开始；阶段 4、5 以编辑引擎定稿为前提。重构剩余验收项按项目进度并行收尾，不阻塞阶段 2 的表结构与 Repository 开发，正式替换数据源前需通过。桌面卡片与选择性 JSON 仍为迁移对象；实施前核对当前代码及所有未提交改动并保留。沿已建立的结构边界推进，不重新执行整份历史重构计划。不同时扩展搜索、文件夹管理、待办或私密功能。
