# 本地持久化与长笔记开发计划

状态（2026-11-12）：阶段 1 未完全验收，不进入正式数据迁移。动态皮肤已合入，R1～R4 结构迁移已实施，但阶段出口尚未全部通过。当前实验见[技术实验结论](../technical-demos.md)，剩余回归见[项目进度](../progress.md)，历史验收依据见[重构历史计划](../archive/2026-11-12-refactoring-plan.md)。

## 已确认范围

- 使用本地关系型数据库保存笔记、正文块、附件信息和编辑位置；图片等二进制内容保留在应用私有文件目录。设置使用独立的小型键值存储。
- 正文文字直接保存在正文块记录中，一条笔记关联多条有序正文块。JSON 可用于块的扩展属性，不把全文作为单个 JSON 附件。
- 支持 10 万字笔记，覆盖无换行长文、多段文字和图文混排。内部拆块不增加换行，不改变原文、复制和分享结果。
- 块采用目标大小、内容边界和硬上限结合的策略。约 2,000～4,000 字符、硬上限约 8,000 字符仅为试验起点，以真机测量确定；不得切断完整字符。局部拆分、合并，不因普通输入重切全文。存储块、语义段落和输入控件不强制一一对应。
- 全局设置提供恢复上次编辑位置开关，每条笔记分别记位置。开启后以浏览态打开并定位，不弹键盘；关闭后从顶部打开。位置记录不更新笔记修改时间或首页排序。
- 使用块 ID、块内光标偏移和内容版本定位；标题位置单独标识。浏览位置与编辑位置分开，单纯滚动不覆盖编辑位置。删除、拆分、合并和撤销后校正锚点，无有效锚点时回退到邻近位置或正文末尾。
- 编辑页先读取、显示目标附近内容，其他部分按需读取和渲染。用估算或缓存高度占位，实际测量后修正；保持可见内容锚点稳定，允许滚动条初始比例不精确。宽度、字号等排版条件变化时使旧高度缓存失效。
- 编辑停顿时自动保留草稿，离页正式保存；已有笔记移动、换肤立即保存相关字段，新草稿随首次内容保存。保存失败保留草稿并提示，离页正式保存失败时留页重试。
- 空白新草稿不创建笔记；清空已有笔记不自动删除；仅含图片有效。撤销重做历史离页清空，不跨进程恢复。
- 首页单独读取摘要和元信息；输入、字数和历史处理避免逐字复制、序列化全文。完整分享、复制等操作覆盖未加载内容。
- 首次初始化可导入样例，删除全部笔记后不重复生成。数据结构有版本及迁移机制。首期保证进程重启恢复，云同步、卸载恢复、导入导出、回收站与私密保护不在本轮范围。

## 阶段 1：现状核对与技术验证

当前门槛：第四轮放弃当前 StyledString 批量与普通整段一次提交路径，保留逐片段比较基线。鸿蒙 Web / CodeMirror 6 四种合成文字基础对照与有限的 RichEditor 能力核对已完成，下一闭环补真实交互与图文可行性，转向原因见[当前实验结论](../technical-demos.md)。完整编辑、真实多进程竞争、按需渲染、精确位置与性能门槛仍待验收；此前测量见[完整实验记录](../archive/2026-11-12-technical-demos.md)。

- 核对主编辑页、桌面卡片和半模态编辑现有保存路径、正文拼接语义、历史快照、文件生命周期及冲突检测。
- 核对本地 SDK 支持的数据库、多入口访问、虚拟列表、定位和输入控件能力，以独立试验验证长文本及跨块输入可行性。
- 准备 2 万字、10 万字、无换行长文、多段图文数据；按下述临时门槛记录冷打开、定位、输入、粘贴、内存与滚动表现。
- 输出最终表结构、分块边界规则、位置偏移单位、默认开关值及性能基线。未实现的跨块全选、复制、输入法与无障碍行为必须在此识别，不能留到最后。

阶段 1 出口：完成上述验证并确定表结构、位置单位与默认开关值，按下述临时性能基线验收；核心编辑或性能不达标时定位瓶颈、限定优化范围后复验，不以方案间排名代替达标判断。

### 临时性能基线（2026-11-12 用户暂时采纳）

先在当前真机 DMG-W00 / OpenHarmony-6.1.1.120 验收十万字无换行与密集多段两种场景；其他设备及图文覆盖另记，不据单设备结果扩大结论。

| 操作 | 验收门槛 |
| --- | --- |
| 打开笔记 | 从打开操作到目标位置可见且可操作不超过1秒，进入编辑后不再明显卡住 |
| 连续滑动 | 帧时间P95不超过33ms，无超过100ms冻结、明显停顿或跳文 |
| 普通输入与退格 | 按键到文字显示更新P95不超过100ms，连续输入不积压、不丢字 |
| 中文输入 | 预输入、选词、退格和光标移动正常，无明显延迟或文字错乱 |
| 中部/尾部定位 | 500ms内显示目标附近内容，后续排版修正不推走正在看的文字 |
| 长文粘贴 | 粘贴2万字后1秒内恢复可操作，内容和撤销结果正确 |
| 内存与稳定性 | 连续打开、编辑、退出10轮不退出、不持续增长；先采稳定占用，再确定明确内存预算 |

按实际端到端操作计时并保留冷/热启动、样本数量、设备与输入方式。帧时间应对应实际显示提交，输入延迟应覆盖按键至屏幕更新；Web requestAnimationFrame、事件回调或事务计时仅作筛查代理，不直接宣称完整达标。系统注入不能替代物理中文输入，视觉跳文、选区及中文行为需真实操作验收。结果逐项标为通过、未通过或待验；缺少测量链路时保留待验，不用已有加载数字填补。方案达标后才比较内存和维护成本，避免无目标追求更小数值。

## 阶段 2：持久化基础与已有数据迁移

- 建立 Repository、版本化数据库和事务，包含笔记信息、有序正文块、附件信息、位置及初始化标记；为后续草稿与内容版本预留结构。
- 接通笔记创建、读取、更新、删除、文件夹移动和换肤；首页读取摘要，不读全文。正式内容更新与摘要、版本更新保持一致。
- 将现有桌面笔记 JSON、删除标记、卡片关联及附件引用迁入统一数据源；迁移可重复执行，中断可恢复，验证成功前保留原数据。
- 主应用、卡片扩展和半模态编辑统一版本检查，冲突时不覆盖更新内容；兼容迁移期旧入口，避免双份数据互相覆盖。
- 验收：重启恢复、删光后不复生、图文/移动/皮肤恢复、迁移重试、写入失败、桌面卡片刷新和多入口冲突。

## 阶段 3：自动草稿与附件安全闭环

- 自动草稿与正式笔记分开，按停顿合并写入变化块；生命周期回调作为补充，不能只依赖退出时保存。恢复草稿需校验正式版本，避免覆盖其他入口修改。
- 明确自动草稿与离页正式保存的状态转换、首次草稿身份及空白草稿清理。离页保存失败保留页面；磁盘满或读取损坏不得静默重置。
- 图片先可靠写入再提交引用。清理时考虑正式笔记、草稿、活跃撤销历史及进行中的导入，不能在文件暂未建立引用时误删。
- 验收：编辑中强制结束进程、恢复图文草稿、保存失败重试、撤销恢复图片、删除与跨进程孤立附件清理。

## 阶段 4：长笔记局部编辑与历史

- 引入不改变文本语义的局部分块、范围读取和增量写入；将全文快照历史改为有内存边界的局部操作历史。
- 解决跨块光标、删除、选择、粘贴、输入法预输入及图片拆分；持续保留活动输入控件，不用内容变化强制重建节点。
- 字数增量维护；摘要、完整文本导出及分享覆盖全部块，耗时操作不阻塞输入。
- 验收：10 万字单段和多段输入/删除、长文粘贴、跨块复制、图片插入、撤销重做及逐字符原文一致性。

## 阶段 5：按需渲染与位置恢复

- 按需创建可见区附近节点，保留活动编辑区；采用高度估算、布局缓存与可见锚点补偿，处理图片高度变化和快速滚动。
- 接通位置保存及恢复；长文中部和尾部直接加载目标附近，禁止先全文渲染再滚动。
- 设置页增加全局恢复开关，仅实现该设置闭环，其余设置不扩展。默认值在阶段 1 确认。
- 验收：顶部/中部/尾部恢复、不弹键盘、开关切换、锚点失效回退、加载不跳文、布局变化和长距离滚动。

## 阶段 6：综合验收与文档收尾

- 按阶段 1 确定的设备与阈值验收 2 万字、10 万字、无换行和图文笔记；覆盖冷启动、已有高度缓存、定位、滚动、输入、分享及内存。
- 回归短笔记、中文预输入、真实剪贴板、删除、图片、皮肤、移动、桌面卡片和半模态编辑；数据层检查之外必须有真机验证。
- 每阶段按 [AGENTS.md](../../AGENTS.md) 命令行构建；调整系统能力时更新[系统能力说明](../system-capabilities.md)，最终同步数据模型、页面规格和项目进度。未通过的项目明确记录，不以构建通过替代性能验收。

## 依赖与实施边界

阶段 1 → 2 → 3 → 4 → 5 → 6。阶段 1 先验证阶段 4、5 的关键可行性，防止数据库落地后才发现编辑控件不适配。每阶段保持一个可运行闭环，不同时扩展搜索、文件夹管理、待办或私密功能。正式阶段 2 还须以重构剩余验收通过为前提。桌面卡片与选择性 JSON 仍为迁移对象；实施前核对当前代码及所有未提交改动并保留。沿已建立的结构边界推进，不重新执行整份历史重构计划。
