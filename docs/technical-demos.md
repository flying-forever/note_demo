## 已确认结论

- 独立数据库试验通过范围读取、条件版本更新、事务回滚、关闭重开及应用进程重启恢复；同进程双句柄不替代真实多进程竞争。
- RichEditor 原生跨片段选区、全选及系统按键复制、粘贴、删除在四种合成文字场景通过。用户于 2026-11-09 确认普通控制器试验在当前设备/输入法下中文预输入、选词、退格与收起键盘正常，不扩大为正式编辑页或全部输入法通过。
- 第四轮放弃当前 StyledString 批量和普通整段一次提交路径，保留逐片段比较基线。批量路径虽缩短部分导入时间，但密集多段的内存成本显著增加；原始耗时/PSS及试验条件仅在[第四轮对照记录](archive/2026-11-12-technical-demos.md)维护，不作为正式冷打开或内存峰值验收。
- 批量连续试验发生过 RssThresholdKiller 退出，后续脚本通过不代表内存问题已修复。逐片段基线也未满足快速打开方向，尚不是正式加载方案。
- 离线 CodeMirror 对照已在当前鸿蒙设备通过2万/10万×无换行/多段四场景的全文、事务撤销重做、模型全选、目标视口和系统文字注入检查。十万多段确实保留全文模型而仅创建局部行节点；Web有额外进程成本，未确认总内存优于普通原生，也未完成中文预输入、手指选区、长文剪贴板或图文选型。新增原生核对前后采样及Web口径见[本轮对照记录](archive/2026-11-12-editor-engine-comparison.md)。
- 按临时基线完成两种十万字样本的三轮系统持续触摸采样及修正采样后的分项复验：内部呈现间隔与插入/退格代理均低于门槛，内容准确；首次呈现个别约105～107ms，整项滑动和端到端输入仍保留待验。结果、修正及缺口见[性能验收记录](archive/2026-11-12-web-performance-baseline.md)。
- 2026-11-12 用户在当前设备对 Web 文字原型完成一组真实中文输入手验：点击定位、预输入与候选词、退格、收起键盘后重新点击继续输入均正常，未见延迟、错乱或丢字。仅当前设备与当前输入法；手指跨屏选区、惯性滚动、长文剪贴板及图文仍未验收。
- 2026-11-12 完成 Web 原型浏览/编辑分离的当前设备手验与自动核对：只读态长按可出选取手柄、系统菜单并支持拖到下边缘自动滚动，不弹键盘，选区可读回模型；点按正文进入编辑后键盘弹出、光标落在点按处，注入 4 字符后长度 100000→100004；切回只读键盘收起。自动化的 `uitest` 长按未复现原生选区，该步以用户手验为准。
- 2026-11-12 Web 原型完成 2 万字真实系统剪贴板粘贴：长按菜单粘贴后长度 100000→120000，页面内 paste 事件至模型更新并完成两个动画帧为 70.2ms，单事务；撤销回到 100000，全文逐字核对一致。剪贴板内容由实验页用系统 pasteboard 写入合成文字，非手工复制。
- 2026-11-12 自动采样手势与图文原型（`uitest` 注入，非真机手感）：十万字多段与无换行持续滑动内部帧 P95 均 13ms、最大 58.4ms、无 >100ms 冻结；滑动与中/尾跳转后视口内无可见文本间隙；中/尾跳转 25～50ms 且目标可见。数据 URI 占位图的 CodeMirror widget 可在 100001 字文档中随滚动与跳转保持渲染。`uitest uiInput text` 不产生可信 keydown/beforeinput；硬件键注入见下条。
- 2026-11-12 图文最小链路通过：3 张内置 JPEG 从 rawfile 复制到沙箱 filesDir/images，读回后按 500KB 上限（当前图片约 16.7KB，未触发压缩空实现）生成 data URI；十万字多段中插入后 100000→100001，滚动、尾部跳转与回中部均保持 images=1 且视口内无可见空白；撤销回 100000、images=0，退格删除回 100000、images=0。真实相册选图、附件表与引用清理未接。
- 2026-11-12 系统按键注入可产生可信事件：`uitest uiInput keyEvent` 发字母键与退格键后，`PerformanceProbe` 收到 25 个可信样本（`uiInput text` 仍为 0），字母键至模型更新加双帧 P95 32.1ms、退格 28.7ms，均无 >100ms；不含中文输入法和显示呈现。
- 2026-11-12 内存分两口径：冷启动 10 轮为不同进程，加载后约 209MB、编辑后约 224MB，无上升趋势；同进程连续 20 次重载十万字，PSS 206→253MB，前 10 轮 +34MB、后 10 轮 +6MB，仍在缓慢增长。209MB 时 GL 38.7MB、Graph 48MB、native heap 57.8MB、ArkTS 堆仅 5.7MB，增长不在 ArkTS 堆，需先定位 ArkWeb 渲染/图形缓冲再判定稳定性。
- 2026-11-12 冷启动代理：强制停止后应用出窗约 1.7s（150ms 轮询粒度），进入实验页一键作耗时约 4.8s、加载后状态可读约 2.5s（含自动化点击与轮询开销）；页面内十万字加载 34～37ms。无正式笔记入口，未按 ≤1s 验收。
- 2026-11-12 阶段 2 数据层落地并真机自检：`notes.db` schema v2（notes/blocks/attachments/positions/settings），旧库升级保留 26 条（墓碑 4）；改标题保存后重启仍在，删除后重启不复生；首页只读摘要、编辑页按 ID 加载整篇（3 块、92 字）并保留附件，新建笔记保存后显示；桌面半模态改标题保存后，主应用首页与卡片均显示新标题，附件引用保持 1；自检通过计数、`migration.desktop_json.v1=done`、单块往返、版本 1→2、过期 revision 写入被拒、附件引用一致、墓碑与清理，重复启动计数不变；图片落盘与逐 ID 迁移校验未验。

## 实验方向调整（2026-11-12）

十万字密集多段的全量 RichEditor 路径已有明显耗时和内存瓶颈，浏览态懒加载只会延后进入编辑时的成本，不能证明问题已解决。多个局部原生输入框还需自行解决全文选区、输入法及撤销，暂不作为默认路线。

下一闭环改为编辑引擎选型：鸿蒙 Web / CodeMirror 6 的完整文档模型与视口渲染基础对照已完成，继续补真实输入、选区和图文可行性；API19 RichEditor公开接口暂未找到内部按需排版控制，核对前批量高内存仍复现。CodeMirror 的文字实验不代表图文笔记适配通过，也不预先决定采用 Web。

依据：[CodeMirror 视口机制](https://codemirror.net/docs/guide/#viewport)、[TextKit 2 非连续排版](https://developer.apple.com/videos/play/wwdc2021/10061/)。借鉴的是文档、选区与显示范围分离；鸿蒙输入法、手指选区、图片及 Web 运行成本仍需本机验证。实验与正式笔记数据隔离；阶段1按评估收尾后进入阶段2数据契约，正式替换数据源前完成复验或明确豁免。
