# 技术实验当前结论

阶段 1 尚未完全验收，实验与正式数据隔离，不进入正式数据库迁移。完整过程、样本、脚本用法与失败证据见[实验历史记录](archive/2026-11-12-technical-demos.md)（2026-11-12 为归档日期）。

## 已确认结论

- 独立数据库试验通过范围读取、条件版本更新、事务回滚、关闭重开及应用进程重启恢复；同进程双句柄不替代真实多进程竞争。
- RichEditor 原生跨片段选区、全选及系统按键复制、粘贴、删除在四种合成文字场景通过。用户于 2026-11-09 确认普通控制器试验在当前设备/输入法下中文预输入、选词、退格与收起键盘正常，不扩大为正式编辑页或全部输入法通过。
- 第四轮放弃当前 StyledString 批量和普通整段一次提交路径，保留逐片段比较基线。批量路径虽缩短部分导入时间，但密集多段的内存成本显著增加；原始耗时/PSS及试验条件仅在[第四轮对照记录](archive/2026-11-12-technical-demos.md)维护，不作为正式冷打开或内存峰值验收。
- 批量连续试验发生过 RssThresholdKiller 退出，后续脚本通过不代表内存问题已修复。逐片段基线也未满足快速打开方向，尚不是正式加载方案。
- 离线 CodeMirror 对照已在当前鸿蒙设备通过2万/10万×无换行/多段四场景的全文、事务撤销重做、模型全选、目标视口和系统文字注入检查。十万多段确实保留全文模型而仅创建局部行节点；Web有额外进程成本，未确认总内存优于普通原生，也未完成中文预输入、手指选区、长文剪贴板或图文选型。新增原生核对前后采样及Web口径见[本轮对照记录](archive/2026-11-12-editor-engine-comparison.md)。
- 按临时基线完成两种十万字样本的三轮系统持续触摸采样及修正采样后的分项复验：内部呈现间隔与插入/退格代理均低于门槛，内容准确；首次呈现个别约105～107ms，整项滑动和端到端输入仍保留待验。结果、修正及缺口见[性能验收记录](archive/2026-11-12-web-performance-baseline.md)。
- 2026-11-12 用户在当前设备对 Web 文字原型完成一组真实中文输入手验：点击定位、预输入与候选词、退格、收起键盘后重新点击继续输入均正常，未见延迟、错乱或丢字。仅当前设备与当前输入法；手指跨屏选区、惯性滚动、长文剪贴板及图文仍未验收。
- 2026-11-12 完成 Web 原型浏览/编辑分离的当前设备手验与自动核对：只读态长按可出选取手柄、系统菜单并支持拖到下边缘自动滚动，不弹键盘，选区可读回模型；点按正文进入编辑后键盘弹出、光标落在点按处，注入 4 字符后长度 100000→100004；切回只读键盘收起。自动化的 `uitest` 长按未复现原生选区，该步以用户手验为准。

## 实验方向调整（2026-11-12）

十万字密集多段的全量 RichEditor 路径已有明显耗时和内存瓶颈，浏览态懒加载只会延后进入编辑时的成本，不能证明问题已解决。多个局部原生输入框还需自行解决全文选区、输入法及撤销，暂不作为默认路线。

下一闭环改为编辑引擎选型：鸿蒙 Web / CodeMirror 6 的完整文档模型与视口渲染基础对照已完成，继续补真实输入、选区和图文可行性；API19 RichEditor公开接口暂未找到内部按需排版控制，核对前批量高内存仍复现。CodeMirror 的文字实验不代表图文笔记适配通过，也不预先决定采用 Web。

依据：[CodeMirror 视口机制](https://codemirror.net/docs/guide/#viewport)、[TextKit 2 非连续排版](https://developer.apple.com/videos/play/wwdc2021/10061/)。借鉴的是文档、选区与显示范围分离；鸿蒙输入法、手指选区、图片及 Web 运行成本仍需本机验证。实验与正式笔记隔离，选型门槛未通过前不迁移数据库。
