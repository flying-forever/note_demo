# 技术实验当前结论

阶段 1 尚未完全验收，实验与正式数据隔离，不进入正式数据库迁移。完整过程、样本、脚本用法与失败证据见[实验历史记录](archive/2026-11-12-technical-demos.md)（2026-11-12 为归档日期）。

## 已确认结论

- 独立数据库试验通过范围读取、条件版本更新、事务回滚、关闭重开及应用进程重启恢复；同进程双句柄不替代真实多进程竞争。
- RichEditor 原生跨片段选区、全选及系统按键复制、粘贴、删除在四种合成文字场景通过。用户于 2026-11-09 确认普通控制器试验在当前设备/输入法下中文预输入、选词、退格与收起键盘正常，不扩大为正式编辑页或全部输入法通过。
- 第四轮放弃当前 StyledString 批量和普通整段一次提交路径，保留逐片段比较基线。批量路径虽缩短部分导入时间，但密集多段的内存成本显著增加；原始耗时/PSS及试验条件仅在[第四轮对照记录](archive/2026-11-12-technical-demos.md)维护，不作为正式冷打开或内存峰值验收。
- 批量连续试验发生过 RssThresholdKiller 退出，后续脚本通过不代表内存问题已修复。逐片段基线也未满足快速打开方向，尚不是正式加载方案。

## 下一步门槛

1. 在同一交互方案验证浏览态按需渲染、块内精确位置、可见锚点与高度补偿，以及原生编辑区创建时机和峰值内存。
2. 补齐真实图片、手指选区、真实剪贴板长文粘贴、Unicode/表情边界、无障碍及完整编辑场景；保留已有单设备输入法结果的范围。
3. 验证主应用/扩展访问、真实多进程竞争；确定最终表结构、位置单位和恢复开关默认值。
4. 用明确设备、多次采样及量化阈值验收冷打开、定位、输入、滚动与内存，不能用控制器调用或回调计时替代完整性能验收。

## 隐私编辑实验（2026-11-13）

本实验与长文/数据库阶段独立，不接正式数据。入口为首页设置长按 → 技术实验室 → 隐私编辑，对应 `pages/PrivacyEditorDemo.ets`；仅内存纯文字样例和临时输入，离页不保存。

首版候选为固定视口原生 `TextArea` 保留完整草稿，按原生光标坐标显示当前视觉行，其余区域不透明遮挡；可比较当前行与上一行，按住临时查看全文，松手/滑出/取消即恢复。键盘收起、页面隐藏、窗口失焦或后台时全遮并取消临时查看，回到前台需主动恢复。开发步骤、状态边界与详细验证矩阵统一维护在[开发计划](plans/privacy-editor-demo-plan.md)。

独立 Demo 已实现且最终 API19 命令行构建、安装成功；一行/两行及自动折行定位、有限实际软键盘拼音选词、收键盘全遮、按住/松手、Home返回与离页重进已有前轮真机采样，详细步骤、证据和局限只维护在[本轮记录](archive/2026-11-13-privacy-editor-demo.md)。这些结果不等于完整人工输入法或隐私保护验收。最终回归前设备出现非预期界面变化，已退避，受干扰阶段不计通过，最终版本 UI 回归待确认。

后续仍需验证持续中文输入/删除/换行、复杂emoji、滚动小窗、跨行选区/放大镜、滑出/取消/多指、其他窗口失焦、瞬时闪露与无障碍；当前浮动键盘遮住部分可见行，体验尚未验收。首页摘要、桌面卡片、输入法候选词、截图和后台任务缩略图不在已确认保护范围，不将遮罩等同于笔记加密或锁定。
