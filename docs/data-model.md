# 数据模型

## 当前实现

`model/Note.ets` 使用 `id`、`title`、`content`、`timeLabel`、`group`。首页从正文生成卡片预览，初始时间沿用假数据的展示文本。`model/NoteStore.ets` 管理进程内数据，编辑页持有独立草稿。

可选字段 `skinId` 保存笔记皮肤标识，缺失或未知时按默认白显示。`model/NoteSkin.ets` 集中定义皮肤配色，供后续接入素材。移动文件夹及保存正文保留皮肤设置。

## 当前图文正文

可选 `blocks: BodyBlock[]` 按顺序存储文字与图片引用；旧笔记首次打开转换为单个文字块。`content` 保持为文字块以换行拼接的纯文本，供首页摘要、字数及纯文本分享使用，不包含图片描述。

可选 `images: NoteImage[]` 保存附件 ID、私有文件路径、应用内文件名、像素宽高、字节数、描述和小号状态。文件在 `filesDir/note-images`，不修改相册源文件。移动文件夹、切换皮肤保留正文与附件。

历史记录保存标题及 blocks 的序列化快照；图片描述和尺寸存于独立附件属性，不随撤销变化。删除节点后，文件和属性保留至离页以支持撤销；保存仅保留正文仍引用的附件，离页删除不被任何内存笔记引用的当前附件。异常退出和跨进程孤立附件清理留待笔记持久化阶段处理。

## 桌面笔记的最小持久化

进入「发送到桌面」预览后，仅对该笔记启用持久保存。完整 Note（含 blocks、images、group、skinId）写入 filesDir/desktop-notes/notes 下独立的版本化 JSON 记录；新建 ID 包含时间戳与进程内序号，避免重启后的计数重复。写入先落临时文件、同步后重命名，再更新内存，写入失败保留原值。其他笔记仍为内存数据。

桌面卡片 ID 按 string 保存，避免 64 位整数精度损失。forms 下每张卡片有独立关联文件，支持多张卡片引用同一笔记。保存、移动、换肤后刷新相关卡片；移除卡片只删除关联，保留笔记。删除笔记写入删除标记，防止同 ID 的假数据在重启后重新出现，并把相关卡片刷新为删除状态。

应用启动及回到前台时从磁盘同步桌面笔记，供 UIAbility、FormExtensionAbility 与 FormEditExtensionAbility 共享数据。半模态编辑保存前比较打开时的记录快照，发现外部修改则拒绝覆盖并提示重新打开；主编辑页回到前台时同步外部修改，有未保存草稿时让用户选择版本。

数据层回归命令：`node scripts/test-desktop-notes.cjs`。脚本使用本机 DevEco 的 TypeScript 编译器；其他环境通过 DEVECO_TYPESCRIPT_PATH 指定 typescript.js。该检查验证选择性保存、应用重启、图片引用、移动/皮肤、写入失败、跨实例更新、多卡片与删除标记，UI 和系统能力仍需真机验收。

## 样式和图片的扩展方向

- 确定样式范围后，可把纯文本正文迁移为带版本的文档。段落中的文本片段可附带加粗等样式，段落与图片可按插入顺序排列。旧纯文本可转成普通段落，保留换行。
- 图片正文节点保存附件 ID。接入持久化时，由应用管理图片文件和引用，在保存、删除时处理文件生命周期。
- 首页摘要和未来的搜索文本从正文提取。加入图片后，判断空笔记时也要检查图片节点，只有图片的笔记可以保存。

## 候选模型

以下字段、默认排序和持久化方案供后续阶段确认。

## Note（笔记）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 唯一标识 |
| `title` | string | 标题（可为空，界面回退为正文首行） |
| `content` | string | 正文纯文本 |
| `createdAt` | number | 创建时间戳 |
| `updatedAt` | number | 更新时间戳 |
| `pinned` | boolean | 是否置顶 |
| `folderId` | string \| null | 所属文件夹，null 为默认 |
| `group` | string \| null | 首页分组名称（旅途/美食/攻略/随记） |
| `color` | string \| null | 标签/卡片颜色，可空 |
| `deleted` | boolean | 回收站标记 |

## TodoItem（待办项）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 唯一标识 |
| `noteId` | string | 所属待办笔记 |
| `text` | string | 内容 |
| `done` | boolean | 是否完成 |
| `order` | number | 排序 |

## Folder（文件夹）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | string | 唯一标识 |
| `name` | string | 名称 |
| `createdAt` | number | 创建时间戳 |
| `order` | number | 排序 |

## 排序规则（默认）

1. 置顶优先
2. `updatedAt` 倒序

## 持久化方案（已确认，待开发）

采用本地关系型数据库与附件目录，正文文字直接存于有序正文块记录，一条笔记关联多个块。设置采用小型键值存储。首页摘要独立读取，正文支持范围读取、增量写入及 10 万字按需渲染。现有桌面笔记 JSON 需要迁入统一数据源，保留多入口冲突保护。

支持自动草稿恢复和可关闭的上次编辑位置恢复；后者以浏览态定位，不弹键盘。分块、保存、迁移与验收计划见 [本地持久化与长笔记开发计划](persistence-plan.md)。上文当前实现保持为现状记录，候选字段不代表最终建表结构。
