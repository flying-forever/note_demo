# 图片显示方案：WebView 里的图片从哪里来

记录日期：2026-11-13。本文是讨论记录，不代表图片块已经实现；当前长文外壳仍拒绝含图笔记。

## 用户疑问

> 图片显示方案到底在讨论什么？自定义协议解决了什么问题，又是怎么让图片显示出来的？

先把问题拆开。图片进长文编辑器，实际有三件事：

1. **文档怎么表示图片**：图片在正文里的位置、块 ID、附件 ID。
2. **WebView 怎么拿到图片像素**：`<img>` 的 `src` 从哪里来。
3. **用户怎么插入和操作图片**：选图、删除、描述、尺寸、详情。

“图片显示方案”只讨论第 2 件。第 1 件是数据模型，第 3 件是交互；三件事不能混在一起。

## 一句话解释

图片文件在应用沙箱里，WebView 不能直接读；显示方案就是决定用哪种方式，把缩略图的像素交给 WebView 的 `<img>`。

## 为什么不能直接写文件路径

图片保存在应用私有目录：

```text
filesDir/note-images/image-xxx
filesDir/note-images-thumbs/image-xxx.thumb
```

文档里只存 `imageId`，不存绝对路径。WebView 默认是隔离环境，不能直接读这个沙箱路径；直接写：

```html
<img src="file:///data/app/.../image-xxx">
```

通常打不开，而且一旦为了它开启文件访问，就把整个应用目录暴露给网页，安全和路径管理都不合适。

所以需要一个“取像素”的适配层。

## 方案一：data URL

### 做法

1. ArkTS 读取**缩略图**文件；
2. 转成 base64；
3. 拼成 data URL：

```text
data:image/jpeg;base64,/9j/4AAQ...
```

4. 交给 Web 里的运行时映射：

```js
imageSources.set('image-xxx', 'data:image/jpeg;base64,...');
```

5. CodeMirror 的图片组件设置：

```html
<img src="data:image/jpeg;base64,...">
```

浏览器直接解码字符串，不需要文件权限，也不需要网络。

### 关键边界

- data URL 只存在**本次运行的 JS 映射**里；
- 不写进 CodeMirror 文档；
- 不写进数据库、不写进草稿；
- 文档里仍然只有图片 ID 和占位符；
- 保存时只回传 ID，不回传 base64；
- 显示的是缩略图，不是原图；原图只在原生详情里打开。

### 代价

base64 比原字节大约多三分之一。缩略图约 100KB，data URL 约 133KB；十几张图就是 1～2MB 的 JS 字符串。图片很多时内存会偏高，而且每次重新打开页面都要重新编码。

### 适合什么时候

适合先跑通完整链路：插入、显示、删除、撤销、保存、旧笔记兼容。传输层以后可以替换，文档模型不用动。

## 方案二：自定义协议

这里说的“协议”不是去系统注册一个 URL Scheme，而是在 WebView 内拦截一个专用地址。

### 做法

HTML 里写：

```html
<img src="note-image://image-xxx?size=thumb">
```

WebView 发现这个地址，不发给网络，而是交给 ArkTS：

```text
WebView：请求 note-image://image-xxx
ArkTS：校验 image-xxx 属于当前笔记
      → 读取 note-images-thumbs/image-xxx.thumb
      → 返回 image/jpeg 字节
WebView：把字节当作图片渲染
```

### 它解决了什么

- 不用把 base64 塞进 JS 字符串，省内存；
- WebView 可以按视口懒加载、缓存图片；
- 文档始终只有 ID，不出现路径或 base64；
- 可以继续关闭 `fileAccess`，只开放一个受控的图片通道。

### 它没有解决什么

- 不解决图片块怎么表示；
- 不解决插入、删除、撤销、保存；
- 不解决描述、尺寸、详情。

它只是把“取像素”的方式从“提前塞字符串”换成“按 URL 请求”。

### 代价

- 需要验证 HarmonyOS 的请求拦截 API、二进制响应、MIME 和缓存行为；
- 要严格限制只能取当前笔记的图片，不能变成任意文件读取；
- 缩略图缺失、文件损坏要有回退。

## 为什么先选 data URL

因为图片组件只关心 `src`：

```text
现在：img.src = dataUrl
以后：img.src = note-image://image-xxx
```

文档、块 ID、保存、草稿、撤销都不变，换的只是“图片来源适配器”。先用 data URL 把数据模型和交互跑通，等图片数量或内存成为问题时，再换自定义协议。

## “原生按钮”是什么

长文页面分两层：

```text
ArkUI 页面层
  ├─ 返回按钮
  ├─ 标题输入框
  ├─ “图片”按钮
  └─ Web 组件
        └─ CodeMirror 正文
```

“原生按钮”就是用 ArkUI 写的 `Button`/`Image`，位于 Web 组件外面，点击后直接执行 ArkTS 代码：打开相册、导入图片、压缩、生成缩略图，再通知 Web 插入占位符。

它不是网页里的 HTML 按钮，也不是系统导航按钮，而是应用自己的 ArkUI 控件。

## 图片在文档里怎么表示

图片不是一段带路径的文本，而是一个独立块：

```ts
BodyBlock { id, text: '', imageId: 'image-xxx' }
```

Web 文档用占位符表示图片位置：

```text
blocks: [文字 A][图片 X][文字 B]
Web 文档: "A\n\uFFFC\nB"
```

- `\uFFFC` 是对象替换字符，一行一个；
- CodeMirror 用 widget 把它替换成图片组件；
- 保存时按行还原：普通行是文字块，占位符行是图片块；
- 图片块保留原块 ID 和 `imageId`；
- 分享、字数、摘要仍使用纯文本，图片和占位符不计入。

## 旧笔记怎么处理

已有含图笔记必须能打开、编辑文字、保存后图片不丢。

打开时：

1. 读到图片块和 `imageId`；
2. 找到附件路径；
3. 确保缩略图存在，没有就补建；
4. 缩略图转 data URL，放进映射；
5. 生成带占位符的 Web 文档；
6. 图片组件用映射里的 data URL 显示。

如果缩略图生成失败：

- 不让 WebView 回退加载几 MB 的原图；
- 显示明确的损坏/占位状态；
- 保留块和附件记录，不静默删除；
- 详情浮层再报具体错误。

保存时只编辑了文字，也要把原有图片块原样带回，不能因为 Web 文档里只有占位符就丢图。

## 图片操作为什么走原生

Web 只负责显示缩略图和编辑文档结构。描述、尺寸、详情、删除仍由原生浮层处理：

- 点图片 → Web 通知 ArkTS → 打开原生浮层；
- 浮层修改后 → 更新 Web 里的图片状态；
- 删除 → 移除占位符，文件等保存/清理规则处理。

这样相册、压缩、附件、缩略图生命周期继续只有一套实现。

## 常见误解

### “data URL 会把图片存进笔记”

不会。它只是本次显示的临时字符串，文档和数据库里仍然只有 `imageId`。

### “自定义协议是一种图片格式”

不是。它只是一个 WebView 拦截地址，返回的还是普通 JPEG 字节。

### “原生按钮是网页里的按钮”

不是。它是 ArkUI 控件，在 WebView 外面；网页里的按钮才是 HTML 按钮。

### “WebView 能直接读 file://”

不能默认这样假设。当前 `fileAccess(false)`，也不应该为了图片打开整个文件访问。

### “显示方案决定图片怎么保存”

不决定。保存仍走 `BodyBlock`/`attachments`；显示方案只决定 `<img>` 的像素来源。

## 当前选择

- 文档表示：`\uFFFC` 占位符 + `imageId` + 独立图片块。
- 显示：先用 data URL，只传缩略图；原图走原生详情。
- 插入：ArkUI 原生“图片”按钮，复用相册、压缩和附件导入。
- 操作：描述、尺寸、详情、删除走原生浮层。
- 旧笔记：必须支持打开和保存，不能丢图。
- 自定义协议：作为后续优化，等 data URL 的图片数量和内存成为问题时再验证替换。

## 还没定的

- 图片很多时的内存上限和降级策略；
- 自定义协议的拦截 API 在 API19 上的实际行为；
- 图片块被删除后，撤销和附件清理的极端时序；
- 图片描述的实时预览是否需要在 Web 内同步。

这些问题不影响先把 data URL 方案做通，但需要在阶段 4b 验收时记录。
